# 公开数据边界与密钥保护

## 本次包含

- 人工编写的 10 条虚构知识记录及 16 条验证问题。
- 独立编写的演示代码、前端、测试、文档。
- 从原站提取并适配默认缓存路径的向量算法模块；没有附带向量数据库或模型文件。
- 原站模块/函数名及技术参数，用于解释实现映射。

## 本次不包含

- API key、访问 token、SSH key、认证 cookie、真实凭据。
- 原站 `.env`、凭据文件、数据库、SQLite 知识包、聊天记录、用户和成绩数据。
- 课程附件、真实教师档案、真实评价内容、内部蒸馏输出。
- 原站 `.git` 历史、服务器地址、连接端口、部署配置和本机路径清单。

独立仓库重新初始化 Git，没有继承原站历史。没有读取原站密钥配置再做字符串替换；采用新文件白名单生成和单个算法模块审查。

## 发布检查怎么做

`python -m scripts.audit_publication` 扫描 Git 暂存区文件，匹配常见凭据格式、赋值、私网地址和不允许的文件类型；只打印问题类型和文件/行号，不输出匹配原文。数据路径只有两份指定 JSONL 被允许，并校验虚构来源标记。

这是辅助门禁，不是“能识别所有密钥”的证明。未知格式仍可能漏检，因此还需要逐文件检查、严格提交清单和在 GitHub 上核对最终文件列表。不要用 `git add .` 从原站仓库批量上传。

`.gitignore` 排除 `.env`、缓存、数据库、日志、构建产物和其他 JSONL。示例文件仅提供变量名和空值。默认测试关闭外部模型，并通过模拟响应测试模型分支。

若后续意外提交密钥，应立即在提供方撤销并替换，再处理远端历史；仅删除最新文件不能使已公开的密钥恢复安全。
