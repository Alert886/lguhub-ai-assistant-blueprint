# 技术实现路径与原站映射

梳理日期：2026-09-30。依据开发工作区中的当前源代码；工作区有未提交修改，因此不把它描述成某个已验证的生产发布版本。原站路径仅用于说明出处，代码与业务数据不作整仓导出。

## 1. 知识获取与数据契约

原站 `scripts/campus_kb/` 下有公开指南、教师资料、官方网页等导入器，以及 `export_lguhub.py` 中对课程、资料目录和评价聚合的受控导出。后者不等于允许公开用户记录或课程文件。

统一记录包含 `id / category / title / content / answer / questions / aliases / source_url`，以及来源、时间、标签、实体等字段。`schema.py` 负责必需字段、分类、稳定 ID、长度限制及部分敏感字段校验。稳定 ID 是后续去重、蒸馏覆盖、索引及引用的共同连接键。

本演示以 `pipeline.normalize` 重建这层契约，采用严格字段白名单，并只接受 `synthetic=true` 和 `example.invalid` 来源。这个标记不能自动证明输入没有隐私；本次发布的每条内容均另行检查，全部人工生成。

## 2. 离线蒸馏与断点恢复

原站 `distill.py` 支持兼容接口生成；`gpu_distill.py` 支持本地 GPU 模型。输入原始资料，输出短答案和多种中英问法。它改善检索表达覆盖和本地直接回答能力，**不更新在线模型权重**。

原站 GPU 脚本可使用量化教师模型；具体硬件连接、模型部署位置、真实知识包和蒸馏输出不发布。`merge.apply_overlay` 按 ID 将合格新答案覆盖到已有底包，未完成或被拒绝的条目保留旧版本；避免“只有部分蒸馏成功就丢掉剩余知识”。其拒绝条件包括空答案、占位邮箱和原文未出现的邮箱。

演示 `pipeline.distill` 提供模板基线与可选模型模式。断点由记录 ID、输入 SHA-256、生成模式及模型名称标识，追加写入并落盘；输入变化时重新生成。`overlay` 对新增数字、邮箱、链接作启发式检查。它并不能检测所有事实幻觉，真实应用必须补充人工审核与数据集评估。中断留下损坏的 JSONL 行会明确报错，应保留文件副本并修复末行后继续；不静默丢弃检查点。

## 3. 知识包与向量

原站 `sqlite_pack.py` 编译 `kb_records / kb_meta / kb_fts`；FTS 优先 trigram，不可用时尝试 unicode61。向量模块把 `title + 前八条问法 + 前360字答案` 编码，归一化后以 float32 BLOB 存入 `kb_vectors`。查询向量与资料向量使用同一模型。

本演示为避免中文 FTS 静默退化，要求 trigram 可用；先写临时 SQLite，再关闭连接后原子替换。Windows 上关闭连接是替换文件前的必要步骤。元信息保存合成源文件哈希。

向量相似度为归一化点积：`cos(q,d) = q·d / (||q|| ||d||)`。直觉是比较表达方向，而不是单纯统计相同字。向量召回可以找到同义问法，但高相似度本身不能证明答案完整或事实正确。

提取的 `assistant/vectors.py` 保留原站关键机制：

- 模型 `BAAI/bge-small-zh-v1.5`，通过 FastEmbed / ONNX Runtime 在 CPU 推理。
- 模型必须预先存在于本地；在线请求不下载模型或远程检查元数据。
- 默认 2 个推理线程；问句向量 LRU 最多 128 条。
- 使用 NumPy 从 BLOB 直接读取 float32；矩阵缓存由知识包修改时间和大小失效。
- top-k 为 8；候选阈值 0.68；达到 0.70 才可进入向量加分。
- 最终展示候选相似度小于 0.62 时不确定；无展示候选时另有 0.50 的域外判断。

**这些值来自代码，不是适用于所有数据集的通用最优参数。** 本次默认合成演示不启用向量，不能据此报告向量质量。

## 4. 在线入口与分流

原站前端 `static/js/site_pet_assistant.js` 向 `/api/assistant/query` 提交问题、最近四条消息和当前页面。`chat_tools_api.py:api_tools_campus_guide_chat` 处理登录、积分预留、服务选择与回答编排；积分发生在分流前，不能假定拒答一定免费。

核心顺序如下：

1. 校验问题，解析有限历史，选择内置模型或用户配置。
2. 隐私问题直接拒答，精确闲聊直接本地返回。
3. 课程推荐走课程目录和聚合指标；课程追问可补上先前推荐意图。
4. 学习计划、解释等通用问题优先精确对话模板，否则走生成模型。
5. 资料查询从当前课程页面补足课程号，再查可见资料目录。
6. 校园问题先追问消解，必要时拆分复合问题。
7. 教师姓名、地点、班车等有结构化快速路径，其余走混合检索。
8. 检查知识包答案是否完整、相关、覆盖意图及向量是否可靠；失败时尝试模型，仍失败则明确无法回答。

本仓库 `Engine.ask` 保留上述主要分支，但没有复制所有校园专用词典、菜单和真实联系人规则。资料/课程分支使用合成记录，不查询用户数据库。默认 HTTP 服务只绑定回环地址；它不是带登录认证的生产 API。

## 5. 候选、排序与复合问题

原站 `search_guide` 在大型 SQLite 包上联合 FTS、词法、姓名候选以及向量候选，再用规则加权排序。问句扩展与原问去重执行。中文使用二/三元查询片段，文档侧保存紧凑连续中文字符串与英文词集合，减少每个 worker 的重复字符串对象。

标题/别名/问法/正文匹配有不同权重，领域规则区分地点、教师、联系方式、宿舍流程等。不是统一的 BM25 + RRF 混合搜索：**RRF 用在复合问题的结果融合，单问有显式领域加权重排**。

RRF 形式为 `score(d) = Σ 1/(k + rank_i(d))`。同一来源被多个子问题排在前面时融合分更高。原站通过 `_rrf_merge_results` 融合；演示独立回答各子问，并在 trace 中展示 k=60 的来源诊断分数，不用它替换子问题各自的首选答案。

演示小数据会扫描所有词法候选；FTS 候选仍真实执行并显示，但不限制最终候选集合。这样无需伪造一个大型生产索引。`score >= 20`、词片段覆盖率 `>= 0.18` 是演示门槛，不应当复制到生产应用当置信度。

## 6. 质量门与模型兜底

原站 `pack_answer_needs_fallback` 检查空答案、垃圾或截断文本、缺失事实、问题不匹配、意图覆盖和向量不确定。教师介绍优先原文结构，避免短蒸馏答案丢掉教育背景和研究经历。

重要边界：若向量 top-1 很高，但最终规则选中另一个向量候选中不存在的记录，仍应判为不可靠。比较的是**展示记录自己的分数**，不是任意邻居的分数。

原站通用生成使用有限历史，最多 800 tokens；默认服务在无历史时可按完整问题和页面哈希缓存。用户自带 key 的请求不共享该缓存。校园兜底提示携带检索证据，要求不编造未知事实。

演示单一兼容接口从服务端环境变量读取配置，只有显式开启才调用。不做共享回答缓存，也不接受浏览器提交 key。失败时只输出异常类别，不返回上游响应、认证头或密钥。
